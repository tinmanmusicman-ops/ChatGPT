Flowchart: Indeed Email-to-Sheet Processor (detailed)

[Start] → main()

  • Log run start, load configuration, and optionally enable Google API debug logging.
  • If requested, clear the worksheet before the run on the first execution.
  • Debug mode flag?
    Yes:
    • Read email_body.txt.
    • Process the payload with process_email_payload() (context = "debug mode").
    • Finish after debug dispatch.
    No:
    • Enter the loop until processed_count reaches max_emails_per_run.
    • Fetch the next unread message via get_unread_email_body().
    • If no email is returned, exit loop with status logs.
    • Otherwise, forward (body, uid, sender, subject) to process_email_payload() and update counters.
    • After the loop ends, log the total processed count.

[get_unread_email_body(cfg)]

  • Connect to Gmail IMAP with SSL and select INBOX.
  • Search for unseen messages in the Primary category via X-GM-RAW.
  • Fetch the first message; decode headers and prefer the original sender if found in a forwarded section.
  • Prefer the HTML part of the payload, and fall back to plain text if needed.
  • Validate the body with is_relevant_job_email():
    False:
    • Unmark the message as seen, copy it to NotRead, delete, logout, return an empty body tuple.
    True:
    • Copy to the Processed label, delete the original, logout, and return (body, uid, source_email, subject).

[process_email_payload(...)]

  • Trim the body and skip if empty, logging the context.
  • Log the source email when provided.
  • Call extract_jobs_from_email(). If no jobs result, log and return False.
  • Use the subject line as a fallback location, enriching missing job locations.
  • Append the extracted jobs to the sheet with append_jobs_to_sheet().
  • Log completion (if a UID exists) and return True.

[extract_jobs_from_email(...)]

  • Track timing and instantiate the OpenAI client.
  • Create the prompt by combining the subject and body, then call the Responses API with EXTRACTION_PROMPT.
  • Parse the raw response, extract the first JSON object, and limit jobs to cfg["max_jobs_per_email"] (default 5).
  • Normalize each job dictionary to include job_name, company info, location, work details, salary, SWOT, decision factors, and URL.
  • Log and return the processed jobs along with the elapsed time.

[append_jobs_to_sheet(...)]

  • Obtain the cached worksheet via get_gsheet_worksheet(cfg).
  • Ensure headers and wrapping/formatting helpers are ready, and load cached URLs.
  • Skip rows whose URLs already exist, build new row values (timestamp, elapsed, hyperlink, metadata, raw SWOT).
  • Append rows through gspread, add new URLs to the cache.
  • Annotate each new row with hover notes, formatting SWOT text for readability.

[Helper branches]

  • is_relevant_job_email(): Checks keywords/domains to heuristically accept job alerts.
  • extract_original_sender_from_body(): Uses regex to pull the true sender from forwarded headers.
  • get_gsheet_worksheet(): Authorizes the service account, opens the spreadsheet and worksheet, and caches the handle.
  • _format_swot_text() and related helpers ensure human-readable notes.

[End]

Logs completion details and exits.
